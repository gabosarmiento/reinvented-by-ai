# Chapter 1 Argument Map

Chapter: When Production Gets Cheap  
Argument map approved for drafting: 11 September 2026

## Reader question

What has changed enough to justify reconsidering the company’s operating model?

## Primary argument

The marginal cost and latency of producing some cognitive and software outputs have fallen, and bounded agents can execute increasingly substantial tasks. That does not make organizational value cheap. It moves the constraint toward selection, context, integration, verification, authorization, and accountability. Companies that treat higher output as the result will create queues and debt around those functions.

## Reasoning chain

### Premise 1

Some production is materially cheaper and faster.

- Evidence: fixed-capability inference prices fell sharply.
- Evidence: meaningful productivity gain in a structured customer-support workflow.
- Evidence: improving agent performance on bounded technical tasks.

### Premise 2

The effect is heterogeneous and system-dependent.

- Evidence: gains differed sharply by worker experience in customer support.
- Evidence: experienced open-source developers were slower with early-2025 tools in one randomized study.
- Evidence: later developer measurement became harder as agent use changed task choice and parallel work.
- Evidence: DORA describes AI as amplifying the surrounding system.

### Premise 3

Value requires more than production.

- An output must be selected, contextualized, integrated, verified, and authorized.
- Each step consumes scarce attention, knowledge, technical capacity, or legitimate authority.
- Producing more candidates can increase the load on every downstream step.

### Implication

The operating bottleneck moves. A company can have faster individuals and a slower system.

### Recommendation

Before scaling AI use, identify the queue created around the newly cheap production step. Measure the decision or outcome cycle, not only the speed of generation.

## Five downstream queues

1. **Selection:** Which generated option deserves attention and commitment?
2. **Context:** Does the work reflect current facts, policy, history, and intent?
3. **Integration:** Can the output enter the real product, process, or customer relationship without creating rework?
4. **Verification:** What evidence makes the work trustworthy enough for its consequence?
5. **Authorization:** Who or what has the right to act, spend, publish, deploy, or bind the organization?

Accountability surrounds all five: who answers for the outcome?

## Counterargument

Powerful agents will eventually automate selection, integration, verification, and authorization too, so redesigning the organization around today’s bottlenecks may be premature.

## Response

Automation can move a queue again; it does not remove the need to design the loop. An agent that selects options needs intent and evaluation. An agent that integrates work needs permissions and tests. An agent that authorizes consequential action has been granted institutional power that must be legitimate and reviewable. The durable design problem is not which step remains human. It is how authority, evidence, and learning move as capabilities change.

## Boundary conditions

- The argument is strongest where work is digital, decomposable, repeatable, and evaluable.
- Physical, relational, safety-critical, ambiguous, or politically contested work may retain different constraints.
- Stable processes should not be made dynamic without benefit.
- Cheaper model calls do not imply cheaper complete systems.

## What would weaken the argument

- Evidence that AI gains pass through interdependent organizations without complementary changes.
- Reliable agents that can own consequences rather than merely perform actions; this is not currently a coherent institutional category.
- Work where generation was never a meaningful constraint.

## Monday decision

Choose one AI-enabled workflow. Stop measuring outputs created. Draw the elapsed path from request to accepted outcome and identify where work now waits. That queue, not the model, is the next operating problem.

## Chapter movement

Open with the production/value distinction → establish cost/capability change → confront heterogeneous productivity evidence → explain the moving constraint → name the five queues → show the option-cost example → end by introducing Hidden Operational Debt as accumulated unresolved queues.
